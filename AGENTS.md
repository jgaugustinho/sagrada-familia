# Project Rules

- **Language**: Always write code, documentation, comments, and rules in English.
- **Preserve user edits**: Always inspect the file on disk first and perform targeted edits (`edit_file`) rather than full-file overwrites (`write_file`).
- **Vue SFC tag order**: `<template>` first, followed by `<script setup lang="ts">`, then `<style scoped>`.
- **Attribute Order in HTML/Vue Elements**: Always place native HTML attributes first (`type`, `class`, `aria-*`, `role`, `id`, `name`, `alt`, `title`, static `placeholder`, etc.), followed by Vue directives and bindings (`v-model`, `:dynamic-props`, `@events` / event listeners).
- **Formatting & Code Style**: Before creating or editing code, read `apps/web/eslint.config.mjs` and strictly follow all rules defined there. Keep HTML/Vue opening tags on a single line. Keep comma-separated CSS selectors on a single line.
- **Design System & Visual Consistency**: Always follow the site's established design tokens and UI patterns defined in `apps/web/assets/css/main.css`, `apps/web/tailwind.config.ts`, and existing components — including color tokens, typography (`font-sans` / `font-serif`), section/element spacing, surfaces (`surface-linen`), shadows, border radii, hover/focus interactions, and reduced-motion support. Avoid hardcoding ad-hoc colors or inconsistent spacing when theme tokens or existing patterns apply.
- **Verification & Checks**: After editing code, run ESLint only on the modified files (`npx eslint <files>`). Do NOT run `nuxt build` or `nuxt generate` unless explicitly requested by the user. Run `nuxt typecheck` only when TypeScript types, props, or composables are significantly changed.
